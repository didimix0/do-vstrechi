# Устройство прототипа

Сервер написан на Python, интерфейс — на HTML, CSS и JavaScript. История попыток хранится в SQLite. Для браузерного текстового режима не требуется сборка фронтенда или GPU.

## Одна реплика

1. Сотрудник вводит текст либо записывает речь. Vosk локально распознаёт запись; текст можно исправить до отправки.
2. Анализатор GigaChat получает историю и реплику и возвращает действия сотрудника в структурированном виде.
3. Python проверяет результат и выбирает реакцию по сценарию, открытым вопросам и состоянию клиента.
4. Отдельный запрос GigaChat формулирует разрешённый ответ с учётом характера. Модель не управляет жизненным циклом сессии.
5. Браузер показывает ответ и при включённой опции озвучивает его доступным локальным голосом.

После звонка отдельный оценщик сверяет историю с критериями и закреплёнными условиями. Программа проверяет структуру и применимость результата и рассчитывает рейтинг.

## Рамки сценария

Первым говорит сотрудник. Клиент сначала приветствует его, затем сообщает о сомнении или отказе. Он учитывает уже полученные объяснения, задаёт вопросы по существу и не должен повторять вопрос без ограничения.

Спешащий клиент реагирует на длинные ответы. Недоверчивый уточняет ограничения. Один сложный вопрос допустимо перенести на встречу с обещанием уточнить; базовые условия таким обещанием не заменяются.

При согласии сотрудник подтверждает время и адрес и спрашивает о наличии оригинала паспорта РФ. При окончательном отказе разговор завершается корректно. Фотографирование паспорта в сценарий не входит. Предел упражнения — 18 реплик сотрудника.

## Оценка

Проверяются представление, работа с причиной сомнения, конкретная польза, точность условий, отсутствие неподтверждённых обещаний, следующий шаг, уважение отказа, реквизиты встречи, вопрос о паспорте и деловая речь.

Рейтинг — доля выполненных применимых критериев, умноженная на 100. Неприменимые шаги скрыты. Общие слова «выгодная карта» или «много кешбэка» не заменяют объяснение количественной выгоды.

При техническом сбое пользователь видит уведомление. Резервная фраза клиента явно помечается. Необходимость проверять результаты LLM сохраняется: программные проверки не дают гарантии отсутствия смысловых ошибок.

## Версии

Для новой попытки фиксируются сценарий и продуктовые материалы. Изменение файлов не должно незаметно менять уже сохранённую тренировку. Архивы в `data/` и `prompts/` обеспечивают воспроизводимость старых фикстур и тестов.

Дообучения весов нет. Три роли используют отдельные инструкции и вызовы модели; фреймворк мультиагентной оркестрации и векторная база для этого прототипа не требуются.
